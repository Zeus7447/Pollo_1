Despliegue rápido de una web con Astro + Directus + Coolify

Cómo convertir una web estática en una aplicación que lee un catálogo desde Directus de forma segura y se despliega sin depender de datos compilados.

Caso aplicado: Pollo Fresa · septiembre 2026

1 · La idea

Arquitectura que se usó

Visitante → Coolify Proxy (Caddy/Traefik) → Astro SSR / Node :4321 → Directus API

La clave es SSR (renderizado en servidor). La página consulta Directus cuando alguien entra al sitio, no cuando se compila la imagen. Por ello se pueden actualizar productos, precios y categorías en Directus sin volver a construir la web.

Qué se logra. El token de Directus nunca llega al navegador; vive únicamente como variable de entorno del servidor. El visitante recibe HTML ya renderizado con los productos.
Qué no funciona para este caso. Un build estático servido por Nginx genera el HTML una sola vez. Los cambios posteriores en Directus no se ven y las variables de runtime no sirven para volver a consultar el catálogo.

Variables que debe tener cada sitio

DIRECTUS_URLURL base accesible desde la aplicación.https://cms.midominio.com

2 · Preparar Astro

Configuración SSR mínima

Instalar el adaptador:

pnpm add @astrojs/node

En astro.config.mjs, configurar salida de servidor y declarar los secretos:

import { defineConfig, envField } from 'astro/config';
import node from '@astrojs/node';

export default defineConfig({
  output: 'server',
  adapter: node({ mode: 'standalone' }),
  env: { schema: {
    DIRECTUS_URL: envField.string({ context: 'server', access: 'secret' }),
    DIRECTUS_TOKEN: envField.string({ context: 'server', access: 'secret' }),
    DIRECTUS_BUSINESS_ID: envField.string({ context: 'server', access: 'secret' }),
  }},
});

Agregar estos scripts y fijar pnpm en package.json:

{
  "packageManager": "pnpm@10.15.1",
  "scripts": {
    "build": "astro build",
    "start": "node ./dist/server/entry.mjs"
  }
}
Por qué fijar pnpm: Railpack puede elegir una versión reciente con políticas de seguridad que rechazan dependencias recién publicadas. Al definir packageManager, Corepack descarga la versión esperada y el build es reproducible.

Leer secretos exclusivamente desde servidor

import { DIRECTUS_URL, DIRECTUS_TOKEN, DIRECTUS_BUSINESS_ID }
  from 'astro:env/server';

const response = await fetch(
  `${DIRECTUS_URL}/items/products?filter[business][_eq]=${DIRECTUS_BUSINESS_ID}`,
  { headers: { Authorization: `Bearer ${DIRECTUS_TOKEN}` } }
);

Nunca uses prefijos públicos como PUBLIC_ para el token. No pongas el token en scripts del navegador, HTML, commits ni capturas.

3 · Directus

Usuario y permisos de solo lectura

  1. Crea una política/rol exclusivo para el sitio web, por ejemplo Website Read.
  2. Da únicamente Read en las colecciones que se mostrarán, por ejemplo products, categories y directus_files.
  3. Asigna la política a un usuario técnico y genera un token estático.
  4. Prueba el token con una consulta de lectura antes de desplegar.
Imágenes. Si el campo de producto contiene el ID de directus_files, la imagen se obtiene por /assets/<id>. La política necesita acceso de lectura a esos archivos, o el producto cargará sin imagen.

URL correcta desde Coolify

DIRECTUS_URL debe ser una URL real y resolvible. El error getaddrinfo EAI_AGAIN tu-dominio-directus significa que quedó un placeholder o un host inexistente.

  • Con dominio público: https://cms.midominio.com.
  • Con Directus en el mismo servidor/red de Coolify: http://HOSTNAME-INTERNO:8055 (usa el Internal Hostname real de Directus).

4 · Coolify

Checklist de despliegue funcional

  1. Selecciona Railpack y sitio Dynamic.
  2. Usa los comandos:
    corepack enable && pnpm install --frozen-lockfile
    pnpm run build
    pnpm start
  3. Agrega las cinco variables de entorno en Runtime. Las tres variables de Directus también pueden estar disponibles durante build, pero lo indispensable es Runtime.
  4. La aplicación escucha en 4321. No es necesario publicar un puerto del host; el proxy de Coolify la alcanza por la red Docker.
  5. Haz redeploy sin caché al cambiar dependencias, build o configuración de proxy.

Cuando se usan etiquetas manuales de proxy

Todos los destinos del proxy deben indicar el mismo puerto interno que Node:

# Traefik
traefik.http.services.<nombre>.loadbalancer.server.port=4321

# Caddy
caddy_0.handle_path.0_reverse_proxy={{upstreams 4321}}

Si hay dos dominios (por ejemplo, con y sin www), actualiza ambas etiquetas Caddy. Mantén las reglas, TLS, dominios y middlewares existentes.

5 · Diagnóstico rápido

Errores comunes y solución

Bad GatewayEl proxy apunta a 80, pero Astro escucha en 4321.Cambia el upstream Caddy/Traefik a 4321; confirma HOST=0.0.0.0.
“El catálogo se está actualizando”La consulta SSR falló y la interfaz muestra el estado de respaldo.Recarga la página y revisa Runtime Logs para la línea [Directus].
EAI_AGAINDNS/host de Directus inválido.Corrige DIRECTUS_URL; no uses placeholders.
401 o 403Token inválido o política sin permiso.Regenera token y habilita Read en productos, categorías y archivos.
ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATIONRailpack instaló una versión de pnpm con política de antigüedad.Fija packageManager: pnpm@10.15.1 y vuelve a subir el commit.

Prueba final antes de entregar

  1. Cambiar o añadir un producto en Directus.
  2. Recargar el sitio publicado.
  3. Comprobar que aparece sin ejecutar otro build.
  4. Revisar que la consola del navegador no contiene el token.
